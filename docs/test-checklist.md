# 実機確認チェックリスト（iPhone Safari / Android Chrome）

このツール環境ではブラウザのGPS・方位センサーAPIを実機なしで検証できないため、
以下の手順を人手でスマホ実機上で確認すること。対象は `docs/spec.md` の受け入れ基準（12章）
および2〜8章の表示ルールに基づく。

## 事前準備

- [ ] HTTPS環境を用意する（`npm run dev -- --experimental-https` またはVercelプレビューURL。README参照）
- [ ] 確認対象デバイスを用意する
  - iPhone（Safari）：できれば2台以上のiOSバージョンで確認（iOS 13以降が対象。`DeviceOrientationEvent.requestPermission` の有無が分岐点）
  - Android（Chrome）：できれば2台以上の端末・Androidバージョンで確認
- [ ] 実際に歩いて距離・方角を確認できる屋外の場所を確保する（建物の密集度が異なる2箇所：見晴らしの良い場所／ビル街や屋内近くなど精度が落ちやすい場所）
- [ ] 目的地の緯度経度を事前に控えておく（例：現在地から徒歩5〜10分程度の地点。Googleマップ等で座標取得）

---

## A. 初期表示・開始ボタン（spec 1章・2章 `initial`）

- [ ] URLを開いた直後、タイトル「街歩きコンパス」と「開始」ボタンのみが表示される
- [ ] フォーム・コンパス・距離表示・GPSラベルが一切表示されていない
- [ ] 画面に現在地の緯度経度、地図、ルート線、方位角の数値、accuracy数値、デバッグ情報が表示されていない

## B. 許可要求フロー（spec 2章「開始ボタン押下時の許可要求フロー」）

### iPhone（Safari）

- [ ] 「開始」をタップすると、まずGPS（位置情報）の許可ダイアログが表示される
- [ ] 続けて方位センサー（モーションと方向）の許可ダイアログが表示される（同一タップ操作の中で発生すること。別のタップが必要になっていないか確認）
- [ ] 両方「許可」を選択した場合、GPSラベルが「取得中」→（数秒後）「良好」または「精度が低い」に変化する
- [ ] GPSのみ許可・コンパスは拒否、という組み合わせでも正常に動作する（コンパス領域が「コンパスが使えません（距離表示のみ有効です）」になる）

### Android（Chrome）

- [ ] 「開始」をタップすると、GPS（位置情報）の許可ダイアログが表示される
- [ ] 方位センサーの許可ダイアログは表示されない（Android Chromeの仕様通り）
- [ ] 許可後、数秒以内にコンパスの矢印が表示される、または3秒程度待っても表示されない場合は「コンパスが使えません」表示に切り替わる（非対応端末・ブラウザの判定）

## C. 目的地設定フォーム（spec 1章・3.2節・7章）

- [ ] 権限確認中（「位置情報・方位センサーの許可を確認しています…」表示中）は緯度・経度の入力欄・ボタンが操作不可（グレーアウト等）になっている
- [ ] 権限確認完了後、入力欄・ボタンが操作可能になる
- [ ] 正しい緯度経度（例：35.6895 / 139.6917）を入力し「目的地設定」を押すと、エラーが出ずに目的地が設定される
- [ ] 緯度に91、-91など範囲外の値を入れると「緯度は -90〜90 の範囲で入力してください。」が表示され、目的地が設定されない
- [ ] 経度に181、-181など範囲外の値を入れると「経度は -180〜180 の範囲で入力してください。」が表示され、目的地が設定されない
- [ ] 緯度・経度に「あ」「１２３」（全角数字）等の数値変換できない文字を入れると「緯度・経度は数値で入力してください。」が表示され、目的地が設定されない
- [ ] 緯度・経度を空欄のまま送信するとエラーが表示され、目的地が設定されない
- [ ] 入力欄に`type="number"`特有の挙動（スピンボタン、全角入力時の奇妙な挙動等）が出ていない（`type="text"` + `inputMode="decimal"`になっているか目視確認）
- [ ] エラー表示後も入力した値は消えずに残っている（再編集して再送信できる）
- [ ] 目的地設定済み（tracking中）の状態でも、フォームに別の緯度経度を入力して再送信できる（目的地の再設定）

## D. コンパス（矢印）表示（spec 3.1節・4.2節）

- [ ] コンパスが有効な状態で、目的地方向へ端末の上部（画面上向き）を向けると矢印が真上（0度）付近を指す
- [ ] その場で端末をゆっくり1回転させると、矢印も連動して回転する（追従の遅延はEMAスムージングによりやや発生するのは正常）
- [ ] 矢印が0度/360度の境界をまたぐときに、逆方向へ1回転してしまう「跳ね返り」が発生していない（359度→0度のような変化時、矢印が一瞬逆回転して1周してしまわないか目視確認）
- [ ] 端末を小刻みに動かした際、矢印が小さくガタガタ揺れすぎない（スムージングが効いているか）。逆に追従が遅すぎて実用に支障が出ていないか（`SMOOTHING_FACTOR=0.2`が適切か所感を記録）
- [ ] コンパスが使えない状態（拒否・非対応・タイムアウト）のとき、矢印の代わりに「コンパスが使えません（距離表示のみ有効です）」が表示される
- [ ] 上記表示中も、GPSによる距離表示・GPSラベル・GoalFormは通常通り動作している（距離表示機能自体は止まっていない）

## E. 残り距離表示（spec 3.3節・5.1節）

- [ ] 目的地設定直後、残り距離が整数m（例：425m）で表示される
- [ ] 実際に目的地に向かって歩くと、距離の数値が徐々に減っていく（リアルタイム更新）
- [ ] 表示される距離がおおよそ正しい（地図アプリ等で別途確認した直線距離と大きく矛盾しない）
- [ ] 目的地未設定時は距離欄に「--- m」またはガイダンス文言が表示され、意味不明な値（NaN、undefined等）が表示されていない

## F. ゴール判定（spec 2章補足・5.4節・12章6項）

- [ ] 目的地から20m以内に入ると、距離表示が大きな「GOAL」に切り替わる
- [ ] GOAL後、20mの範囲外に出ても（目的地から離れても）「GOAL」表示が維持され続ける（tracking表示に戻らない）
- [ ] GOAL状態のままフォームで新しい目的地を再設定すると、GOAL表示が解除されtracking状態（矢印＋残り距離）に戻る
- [ ] ゴール判定の20m境界付近（19m、20m、21m程度）で不自然な表示のチラつき・切り替わりの往復が起きていないか確認

## G. GPS精度ラベル（spec 4.1節）

- [ ] 許可確認中は「取得中」と表示される
- [ ] 位置情報取得済みでaccuracyが良好（20m以下目安）な場合は「良好」と表示される
- [ ] 建物の多い場所・屋内に近い場所など精度が落ちる環境で「精度が低い」に切り替わることを確認する
- [ ] GPS拒否・非対応の場合は「未許可」と表示される
- [ ] 画面上にaccuracyの具体的な数値（メートル数）が表示されていない

## H. エラー処理・許可拒否時の案内文（spec 8章・8.1節）

- [ ] GPSを明示的に「拒否」した場合、「位置情報の利用が許可されていません。端末の設定を確認し、ページを再読み込みしてください。」＋「再試行」ボタンが表示される
- [ ] 「再試行」ボタンを押すと、ブラウザが拒否を記憶していない場合は再度許可ダイアログが出る
- [ ] ブラウザ/OSが拒否を記憶している場合、再試行してもダイアログが出ないことを確認し、8.1節のiPhone/Android別の設定変更手順の案内文が画面に表示されていることを確認する
- [ ] 案内文の手順通りに実際に端末の設定を操作し、位置情報が許可できることを確認する（iPhone：設定＞Safari＞位置情報、Android：アドレスバーの鍵アイコンからサイト設定）
- [ ] コンパスを拒否した場合（iPhoneのみ発生しうる）、コンパス領域の常設表示に加え、エラー表示領域に「方位センサーの利用が許可されていません。端末の設定を確認してください。」が表示される
- [ ] コンパス拒否時の案内文（iPhone：設定＞Safari＞モーションと方向のアクセス）の手順通りに操作し、ページ再読み込み＋再度「開始」を押すことで矢印が有効になることを確認する
- [ ] Android等でdeviceorientationabsoluteが発火せず「非対応」と判定された場合、「この端末・ブラウザは方位センサーに対応していません。」が表示され、距離表示のみで利用継続できることを確認する
- [ ] GPSが一時的に取得できない状態（電波の悪い場所、GPS感度が落ちる屋内等）になっても、「位置情報の利用が許可されていません」という拒否エラーには遷移せず、「取得中」表示や「GPSの電波を取得できません。屋外の見晴らしの良い場所に移動してください。」の表示になることを確認する（denied表示に誤って切り替わっていないか）

## I. デザイン・視認性（spec 1章デザイン方針）

- [ ] 屋外の直射日光下で画面を見ても、矢印・文字が視認できる（コントラストが十分か）
- [ ] 距離表示の文字サイズが十分大きい（48px以上の見た目になっているか）
- [ ] 矢印のサイズが画面幅の50%程度を占める大きさになっているか
- [ ] 375px幅程度の小さい端末でもレイアウトが崩れていない（文字の折り返し、ボタンの押しづらさ等がないか）
- [ ] 端末を横向きにしても、レイアウトが大きく崩れたり操作不能になったりしない（横向きロックはしない仕様なので、多少の見切れ程度は許容）

## J. PWA（spec 9章）

- [ ] iPhone SafariでURLを開き、「共有」→「ホーム画面に追加」した際、アプリ名・アイコンが正しく表示される
- [ ] Android ChromeでURLを開き、「ホーム画面に追加」した際、アプリ名・アイコンが正しく表示される
- [ ] ホーム画面から起動した際、`display: standalone`によりブラウザのアドレスバー等が表示されず単独アプリのような見た目になる

## K. 複数端末の独立動作（spec 0章）

- [ ] 2台の端末で同じURLを同時に開き、それぞれ別の目的地を設定しても、互いに干渉しない（片方の操作が他方に影響しない）ことを確認する

## L. 座標の貼り付け対応（spec 3.2節・15章・12章10項）

### 基本動作（Googleマップからコピーした実際の座標で確認）

- [ ] Googleマップ（アプリ or ブラウザ版）で任意の地点を長押し→ドロップされたピンの座標表示をタップしてコピーする
- [ ] コピーした座標を緯度欄に貼り付け（長押し→「貼り付け」）→ 緯度欄・経度欄の両方に自動で値が振り分けられることを確認する
- [ ] 同じ座標を経度欄に貼り付けても、同様に緯度欄＝緯度・経度欄＝経度に正しく振り分けられることを確認する（貼り付けた欄に関係なく常に緯度欄に緯度・経度欄に経度が入ることを確認）
- [ ] 貼り付け後、値を変更せずそのまま「目的地設定」を押すと目的地が正しく設定される

### iPhone（Safari）

- [ ] 入力欄を長押しして表示される「貼り付け」メニューから貼り付けた場合も自動振り分けが動作する
- [ ] メモアプリ等で全角文字（全角カッコ・全角カンマ・全角スペース）に変換された座標文字列をコピーし、貼り付けても自動振り分けが動作する（例：`（35.1371196，138.6607245）`）
- [ ] クリップボードアクセスの許可ダイアログ等が表示されずに貼り付けができる（`onPaste`イベントベースのため追加の許可は不要なはず）

### Android（Chrome）

- [ ] 入力欄を長押しして表示される「貼り付け」メニューから貼り付けた場合も自動振り分けが動作する
- [ ] Googleマップアプリからコピーした座標（Android版の座標コピー書式）を貼り付けても自動振り分けが動作する

### 境界・異常系（実機での目視確認）

- [ ] 数値が1つだけの文字列（例：`35.1371196`）を貼り付けると、貼り付けた欄だけにその値が入り、もう片方の欄は変化しない（従来どおりの単純貼り付け）
- [ ] 座標と無関係な文章（数字を含まない、または数字が3つ以上ある文章）を貼り付けると、ブラウザ標準のペースト動作（貼り付けた欄にそのまま文字列が挿入される）になる
- [ ] 範囲外の値を含む座標文字列（例：緯度が91になるような値）を貼り付けた場合、貼り付け時点ではエラーが出ず、「目的地設定」を押した時点で通常の範囲外エラーが表示されることを確認する
- [ ] 貼り付け後も入力欄は通常のテキスト入力として編集可能（貼り付け後に手動で値を修正できる）

## M. 目的地のlocalStorage保存・復元（spec 5.7節・16章・12章11,12項）

### 基本の保存・復元動作

- [ ] 目的地を未設定の状態でURLを開くと、GoalFormの入力欄が空である（前回の保存が無い場合）
- [ ] 緯度・経度を入力し「目的地設定」を押して目的地を設定した後、ページをリロード（再読み込み）すると、「開始」ボタンから再度操作を始めた際にGoalFormの入力欄に前回設定した緯度・経度が自動的に入っている
- [ ] 上記の状態で改めて「開始」を押し許可フローを完了させると、矢印・距離表示がすぐに（目的地を再入力しなくても）前回設定した目的地に対して機能する
- [ ] リロード直後は距離表示が「GOAL」ではなく、残り距離（m）表示から始まる（前回ゴールしていた場合でもGOAL表示が復元されないことを確認）。目的地から20m以内にいる場合は、復元後すぐに「GOAL」に切り替わってもよい（これは20m判定ロジックが正しく働いている結果であり、GOAL状態そのものが保存されていたわけではないことに注意）
- [ ] 目的地を再設定（2回目の「目的地設定」）した後にページをリロードすると、2回目に設定した値（最新の値）が復元される（古い値が残っていない）
- [ ] タブ・ウィンドウを閉じて、しばらく経ってから（同じブラウザで）再度URLを開いても、保存された目的地が復元される（セッション内だけの一時保存ではなく、永続的なlocalStorageであることの確認）

### プライベートブラウズモード・localStorage無効環境

- [ ] iPhone Safariのプライベートブラウズモードでページを開き、目的地設定・コンパス表示・距離表示が通常通り動作することを確認する（エラーや画面停止が発生しないこと）
- [ ] 上記の状態で目的地を設定後、同じプライベートタブ内でページをリロードしても構わない（保存されないため入力欄は空に戻る）し、エラーが出ないことを確認する
- [ ] Android Chromeのシークレットモードでも同様に、目的地設定・コンパス表示・距離表示が通常通り動作し、エラーや画面停止が発生しないことを確認する
- [ ] （可能であれば）ブラウザ設定でサイトごとにCookie・サイトデータをブロックした状態で開き、同様に通常動作することを確認する（localStorageが使えない状況の再現）
- [ ] プライベートブラウズ・localStorage無効環境のいずれでも、コンソールにエラーが出力されていない、または画面がフリーズ・白画面になっていないことを確認する（開発者ツールで確認できる場合は確認する）

### GOAL状態が保存されないことの確認

- [ ] 目的地まで実際に近づき「GOAL」が表示された状態でページをリロードすると、GoalFormには目的地の緯度・経度は復元されるが、画面はGOAL表示ではなく計測中（矢印＋残り距離）表示から始まる
- [ ] 上記のリロード後、GPSが目的地から20m以内の位置を示している場合は、ほぼ即座に「GOAL」表示へ再度切り替わる（これは保存されたGOAL状態の復元ではなく、距離計算によって都度再判定された結果であることの理解を確認する項目）

## N. 座標を貼り付けボタン（クリップボード読み取り、spec 17章・12章13〜15項）

### ボタンの基本表示・配置

- [ ] 「📋 Googleマップの座標を貼り付け」ボタンが、緯度・経度の入力欄の直前（上）に表示されている
- [ ] 権限確認中（「位置情報・方位センサーの許可を確認しています…」表示中）はボタンも入力欄と同様に操作不可（グレーアウト等）になっている
- [ ] 権限確認完了後、ボタンが操作可能になる
- [ ] 緯度欄・経度欄のプレースホルダーが「緯度　例：35.137（貼り付け可）」「経度　例：138.660（貼り付け可）」になっている

### iPhone（Safari）でのクリップボード読み取り許可

- [ ] Googleマップで地点をコピーした状態でボタンを押し、初回はクリップボード読み取りの許可ダイアログ（表示される場合）で「許可」を選ぶと、緯度欄・経度欄に自動で値が振り分けられる
- [ ] 許可ダイアログで「許可しない」を選んだ場合、「入力欄を長押しして貼り付けてください」が表示され、緯度欄にフォーカスが移動する（キーボードが表示される等で確認）
- [ ] 2回目以降、許可状態が記憶されている場合はダイアログが出ずにそのまま読み取り・振り分けが行われる

### Android（Chrome）でのクリップボード読み取り許可

- [ ] Googleマップアプリ・ブラウザ版で座標をコピーした状態でボタンを押し、許可ダイアログ（表示される場合）で許可すると、緯度欄・経度欄に自動で値が振り分けられる
- [ ] 許可を拒否した場合、「入力欄を長押しして貼り付けてください」が表示され、緯度欄にフォーカスが移動する
- [ ] HTTPS環境（`next dev --experimental-https` またはVercelプレビューURL）以外（通常のHTTP）ではボタンがエラーなく「読み取り失敗」扱いになることを確認する（secureContext必須、17.2節）

### Googleマップから実際にコピーしてボタンで貼り付け（成功ケース、12章13項）

- [ ] Googleマップで地点を長押し→座標表示をタップしてコピーする
- [ ] 街歩きコンパスに戻り「📋 Googleマップの座標を貼り付け」ボタンを押すと、緯度欄・経度欄の両方に自動で値が入る（1番目の数値が緯度、2番目が経度になっていることを確認）
- [ ] 貼り付け直後は`onSubmit`（目的地設定）が自動では呼ばれず、画面が目的地設定済み状態に遷移していないことを確認する（入力欄に値が入るだけ）
- [ ] 貼り付け後、値を変更せずそのまま「目的地設定」ボタンを押すと目的地が正しく設定される
- [ ] 全角カッコ・全角カンマ付きの座標文字列（メモアプリ等で変換したもの）をコピーしてボタンを押しても同様に振り分けられる

### クリップボードが空／座標として解析できない文字列の場合（12章14項）

- [ ] クリップボードを空にした状態（他のテキストをコピーしていない、またはクリップボードをクリアした状態）でボタンを押すと、「座標が見つかりません。Googleマップで地点を長押しして座標をコピーしてください」がフォーム内に表示される
- [ ] 座標と無関係な文章（数字を含まない、または数字が3つ以上ある文章）をコピーした状態でボタンを押しても、同じメッセージが表示される
- [ ] 上記いずれの場合も、緯度欄にフォーカスは移動しない（読み取り自体は成功しているため）
- [ ] 上記いずれの場合も、入力欄の既存の値は変更されない

### クリップボード読み取りが拒否された場合の表示とフォーカス移動（12章15項）

- [ ] クリップボード読み取りのAPI自体が使えない（非対応ブラウザ、HTTP環境等）場合、「入力欄を長押しして貼り付けてください」が表示され、緯度欄にフォーカスが移動する
- [ ] クリップボード読み取りの許可を明示的に拒否した場合も同じ表示・フォーカス移動になる（PC版Chrome等で権限ブロックして代替確認してもよい）
- [ ] 読み取り失敗時、入力欄の既存の値は変更されない
- [ ] 読み取り失敗時のメッセージ表示後、緯度欄に続けてキーボードから直接入力できる（フォーカス移動が入力を妨げていない）

### メッセージ表示領域・クリア条件（spec 17.4節）

- [ ] ボタンのメッセージ（青系の案内文字色）と「目的地設定」時の入力エラー（赤文字）が、視覚的に区別できる
- [ ] ボタンでエラーメッセージが表示された状態で、緯度または経度の入力欄をキーボードで編集すると、メッセージが消える
- [ ] ボタンでエラーメッセージが表示された状態で、緯度・経度いずれかの欄に（Googleマップ等からコピーした）座標ペアを長押し貼り付け（15章の直接貼り付け）した場合に、古いメッセージが表示され続けないか確認する（表示され続ける場合は不具合として記録する）
